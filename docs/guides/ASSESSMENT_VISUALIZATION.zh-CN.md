# 评测结果可视化

打开「主动评测」后，先显示工作区概览和最近的评测记录，再显示新建评测和仓库部署配置。记录支持 Agent / 题集 / ID 搜索、类型筛选和分页；选择记录会定位到报告。仓库任务会通过已保存的关联显示 `owner/repository` 名称，报告中仍保留原目标 ID。报告地址中的 `id` 保留所选评测，刷新页面仍可继续查看。

## 评分如何阅读

题集得分 = 确认通过次数 ÷ 计划执行次数 × 100。各预算和重复执行都按执行次数计入分母，不对预算得分或维度得分做简单平均。证据不足和未取得结果保持待确认；尚无结果时显示「—」。有待确认项时展示它们全部通过后的得分上限。分数只描述该固定题集的表现，不是通用能力排名。

- 评分环：题集得分及确认通过 / 计划次数。
- 完成度：已取得结果 / 计划次数；执行完成不等于验收通过。
- 能力雷达：覆盖维度的确认通过率；至少 3 个维度才绘制。未取得结果的维度不绘制得分点，未覆盖维度不加入坐标轴。
- 维度条形图：通过、未通过、待确认分别以蓝色、棕色、斜线纹理展示，并提供文字计数。点击维度后自动定位到对应案例，可清除筛选。
- 预算表现对比：每个预算的通过率、平均观测耗时与 Token。未知耗时保持未知，部分 Token 保留 `≥`，离线校准显示不适用。
- 重复结果一致率：结果一致组 / 有完整通过或失败证据的重复组。一致包括重复失败；证据不全的组另列，重复不足时不提供比率。

「统计预算」可以切换全部预算或单一预算。原始预算和维度表保留在「预算与维度 · 原始统计」中，案例证据和导出入口继续可用。旧报告缺少维度数据时展示空状态，并保留现有案例证据。

控制示例标为校准分数；`purpose=adapter_validation` 的接入检查单独标识，不纳入正式评测数量。列表接口保留 `purpose` 字段；前端也可从已保存的仓库任务关联识别接入检查，兼容尚未重启的旧服务。版本比较仍由服务端检查可比性；只有可比时展示两份题集得分与回归计数，修改选择会清除旧比较。

## 验证

`web/tests/assessment-visualizations.spec.ts` 覆盖评分分母、预算切换、维度汇总、未知 / 未取得结果、重复一致率、案例联动、历史报告、校准 / 接入检查、分页与报告地址、不可比版本，以及 1440 / 768 / 390 / 320 像素宽度下的溢出检查。原有主动评测、题集生成、源码规划、Token 和导出流程继续由原有端到端测试验证。
