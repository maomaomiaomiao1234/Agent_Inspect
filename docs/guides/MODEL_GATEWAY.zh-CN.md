# 受控模型网关试点

网关在评审进程中接收目标的模型请求，向配置的供应商转发，并把调用和用量写入 SQLite。它独立于被测容器：目标退出、任务 HTTP 连接断开或没有返回答案时，已经写入的用量仍然保留。

首版支持 **Python LLM 自动适配 + Docker + OpenAI 兼容 Chat Completions/Responses**，包含 JSON 和 SSE、同步/异步客户端。该选项默认关闭。smolagents 固定配方、仓库自带部署清单和其他网络协议暂未接入，不会静默回退成直接调用。

## 启用

先保留现有模型配置。真实供应商地址、模型和密钥仍由服务端 `.env` 选择；网关不会使用适配生成模型的凭据替代目标模型凭据。

本机 Docker 需要能够访问网关监听地址。将以下非密钥配置添加到服务端 `.env`，然后重启评审服务：

```dotenv
# 默认监听 127.0.0.1；容器通过宿主地址访问时使用 0.0.0.0。
AGENT_REVIEW_GATEWAY_HOST=0.0.0.0
# Docker Desktop 的宿主访问地址。其他运行环境需提供可达的宿主机名/IP。
AGENT_REVIEW_GATEWAY_ADVERTISE_HOST=host.docker.internal
```

网关在首次使用时选择空闲端口，只有模型转发端点，所有请求都要求有效短期凭据。它跟随评审服务关闭。Linux Docker 需要自行配置容器可达的宿主地址；本轮实际容器验收环境为 macOS Docker Desktop。

网页操作：

1. 启动 `uv run agent-review serve`，打开主动评测页面。
2. 填写未知 Python Agent 仓库地址，选择真实模型模式。
3. 展开「配置构建与题集」，勾选「通过模型网关保留用量（Python 自动适配试点）」。接入方式会切换为 LLM 自动适配。
4. 提交任务。接入检查与正式题集均通过网关，适配生成请求仍独立统计。

CLI：

```sh
uv run --env-file .env agent-review assess-repo \
  https://github.com/OWNER/PYTHON_AGENT --recipe llm --backend openai \
  --model-gateway --cases 1 --data-dir ./review-data-gateway
```

API 的仓库评测输入增加可选 `"model_gateway": true`。无需提供网关凭据或端口；凭据由评测器逐轮生成，原 `target-v1` 请求 JSON 保持兼容。独立部署目标暂不支持仅在登记表中启用这一选项。

## 凭据和任务关联

每个任务轮次获得一份短期凭据，绑定 `assessment_id/case_id/budget_id/attempt/session_id/turn` 和该轮剩余预算。网关从持久化的凭据映射读取归属，不接受目标提交的任意任务 ID。数据库只保存凭据哈希；原始短期凭据和供应商密钥不写入调用记录。

生成容器的模型地址替换为网关地址，模型密钥替换为占位值。评审器通过单独请求头发送短期凭据，固定适配器在实际 httpx 请求处替换鉴权头。供应商密钥由评审端注入上游请求，不注入容器。任务返回或失败后撤销该轮凭据；过期和撤销的凭据不能发起新请求。

网关只转发配置的模型与两个固定 API 路径，不接受目标指定上游 URL、查询参数或另一模型。调用前写入 `running` 记录，采集到用量后持久化，再转发相关响应数据。JSON 响应在有界缓冲内解析并保存用量后转发；SSE 逐片段采集并转发。

## 用量如何读取

评测详情新增「模型网关记录」，展示持久化请求数、未结束数以及网关路径的 Token。它在目标失败和评审服务重启后仍可读取。

- `job.gateway`：网关路径的持久化汇总，取自数据库。
- 评测证据包的 `gateway.events`：逐次网关事件，包含独立调用 ID、供应商请求 ID、模型、用量、耗时和任务归属。
- 案例与预算的 `usage.fields.*.source=gateway`：从网关记录选取用量。
- `usage_summary.provenance=gateway_reported`：来源是网关采集的供应商报告，不是已核对账单。
- 原始目标轨迹保留在 `artifacts.assessment.turns[].trace`，用于对照；网关证据在同轮 `gateway` 字段中。

网关为每次上游请求生成独立 `gateway_request_id`，通过响应头回传。相同供应商响应 ID 的两个实际请求仍分别记账；重试也是新请求。目标采集器观察到该网关 ID 时，将原工具的模型父调用关联到网关事件。通用轨迹只保留网关模型事件和目标工具事件，避免同一次模型请求出现两份用量。不能关联的目标原始调用仍可在轮次材料中查阅，不直接相加。

对于启用网关的轮次，统计始终选取网关这一来源。即使目标自报更大的用量，也不把两份来源相加；网关之外的调用可能缺失，因此案例级用量保留 `partial / ≥`。网关路径本身的汇总可以完整，但这不证明目标的全部模型调用都经过网关。

## 中断、预算和恢复

目标断开后，网关对已发出的上游请求继续在原有期限内接收结果，以尽可能取得末尾 usage；不会另发重试请求。任务结束时先撤销凭据，最多等待 3 秒收集已有响应，然后取消未结束的网关读取，保存部分记录。停止本地读取不保证供应商立即停止计费。

评审进程也被强制终止时，数据库中已提交的记录保留；重启会撤销全部旧凭据，把未完成调用标为 `interrupted`、`usage_complete=false`，保留已知下界，且不重放请求。如果结束前供应商尚未返回 usage，Token 仍为未知。

每轮最多 180 次请求，每场评测最多 2000 次；同轮最多一条正在执行的上游请求，不同案例可并发。剩余输出预算扣减已知 output Token，并限制下一次模型请求。存在缺失用量时无法证明总消耗未超预算。上游 HTTP 总期限取该轮剩余期限并保留 1 秒收尾；请求体上限 1 MiB，响应总量上限 16 MiB，SSE/JSON 解析仍使用有界缓冲。模型协议或用量冲突不会被包装成完整有效数值。

## 范围与后续

这是项目内的最小网关，没有引入 LiteLLM、额外数据库、价格表或虚拟密钥管理服务。LiteLLM 的持久化用量路线需要数据库配置；后续可在现有任务凭据和外部证据边界上增加适配。参考 [LiteLLM 用量日志](https://docs.litellm.ai/docs/proxy/cost_tracking)。

当前容器仍有普通出站网络，尚未强制禁止绕过网关；跨任务共用同一目标进程也不提供抵抗恶意凭据交换的证明。首版不宣称全模型覆盖、供应商账单认证或多租户隔离。评审进程退出后的未返回用量仍不能凭空还原；若需要网关在整个评审服务故障时继续运行，应进一步拆分为独立服务。

下一步建议用固定真实 Python 仓库验证网关接入兼容性，再扩展独立网关进程、出站限制、更多适配器和跨进程关联。实际合成 SDK/容器/强制退出与浏览器验收见 [网关验收记录](../validation/MODEL_GATEWAY_VALIDATION.zh-CN.md)。
